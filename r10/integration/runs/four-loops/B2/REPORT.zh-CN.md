# 大 loop 2：未利用的下路与缺失的接收答句

24 条逻辑场景：8 条哈希绑定复用基线 + 16 条新轨迹。共同30s窗口，基线4/8、候选3/8、未见4/8存活。不能称通过率改善，也没有覆盖图尾。

## 诊断 → 并行小 loop → 集成
- B1显示slider一直使用上路，长高位巡航单调；原provider其实已有lower分支及由分支推导的phase，属现有概念未利用
- v5 alternate slider调用真实lower provider，保持phase协变；入口240..440，岛体离散下移20/30/40px，形成向下进入+抬升接收，而不是只给虚线画波浪。原8实体数量不变。Cloister承接仍用明确高入口；一条确切probe通过，并非任意出态已保证
- spring的primitive不缺，缺少接收后“回答”关系。alternate在原接收后增加普通墙顶下答句，原弹簧/门不动，两种到达方式都需下降。按easy/medium/hard最小几何下降14/24/34px，仅几何要求，不是难度标定
- 实际集成修正：spring有新答句时，接缝不能再取旧gate中心作出口；使用保留的低位终段cue。没有重置状态/时钟
- 两条预登记小probe均原生win（13.833s、14.875s），保存完整证据。仅验证两个具体场景，不能把单段/局部probe资格转给批量图

## 结果与取舍
批量里下路改变进入下一段时的y/vy，暴露旧潮汐/光轨边界：候选706在18s激光上边失败，707在11.4s潮汐roof-3失败。保留失败，不能挑换种子。

限定保留两种新动作/造型关系作为实验候选；拒绝“v5整体更好/普遍安全”结论。进入B3时以完整v5作实验基线，专门检验 carried-state 关系修订，不称v5合格发布版。

图片visuals-after包含成功前缀和失败；每个命中实体以result和同tick原生body为准，montage不是同一时刻快照。复用第一次因metadata措辞不一致被正确拒绝，regeneration-attempt原样保留；最终直接复制冻结B1地图并验证所有相关hash。
